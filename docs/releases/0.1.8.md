# Typsite 0.1.8

## Before upgrading

- Use the **latest stable Typst**; this release is tested with **0.15.1** and CI
  also checks rolling latest. Older Typst versions are not a compatibility target.
  Building Typsite from source requires **Rust 1.89 or newer**.
- Back up articles, `root/lib`, and `.typsite`. Generate a separate reference with
  `typsite init --dir ../typsite-018-reference`, then merge updated helpers and
  templates rather than initializing over your existing site. Merge the helper
  set `lib.typ`, `site.typ`, `html.typ`, `rewrite.typ`, `rule.typ`, and the new
  **`root/lib/links.typ`** together. The latter is required by `site.typ` and
  `rule.typ`, including HTML-only builds.
- The executable is 0.1.8, but the bundled Typst package retains
  **`@local/typsite:0.1.0`**. Merge the updated `inline-math` helper and `rss` import;
  do not change package imports to `@local/typsite:0.1.8`.

## Cache versus output ownership

Build caches are disposable. Old formats rebuild automatically, and damaged or
missing binary cache manifests/resources recover as misses. Keep the output
journal **`publish/.typsite-outputs.json`** (or the file in your chosen output
root): it is not a cache. It records which outputs Typsite may remove when pages
are deleted or renamed, while preserving unrelated files. Corrupt ownership
metadata fails closed; deleting it explicitly relinquishes old output ownership.

`clean` now validates roots, protects sources/configuration, and shares build
locks. Unmarked nonempty legacy directories need `clean --force` **after checking
the paths**. Pass `--input` and `--config` for nondefault protected roots.

## Stricter validation and truthful failures

Malformed schemas, HTML envelopes, rewrites, themes, syntax definitions/metadata,
and duplicate resource identities now fail even when unused. Recursive embeds,
parent inheritance, and metadata dependencies fail instead of hanging; ordinary
citation cycles remain valid. Unsafe/overlapping roots, escaping output paths,
symlinks in managed output paths, and case/file-directory collisions are rejected.
Export, rendering, and publication failures no longer report a successful CLI exit.

Publication remains atomic **per file**, not for an entire site. Published files
retain data syncing and ownership journals; an interrupted publication can mix
complete old/new files. Fix the error and rerun. Disposable caches may be lost
on power failure and are verified/rebuilt rather than trusted.

## Parallelism and resource use

Automatic article-export concurrency now follows the available **CPU/Rayon
budget**, not a fixed four-article cap. Each Typst child gets a share of that
budget, but more concurrent articles can still use more memory. Use
**`typsite compile --jobs 1`** for low-memory or export-debugging environments, or
set another positive limit with `--jobs N` / `-j N`. `RAYON_NUM_THREADS` controls
ordinary hashing/parsing/rendering work separately. Job-count changes do not
invalidate content caches. Performance gains are workload-dependent; some larger
cold/no-op measurements still regress versus 0.1.7 while durability is retained.

## RSS and preview

RSS is opt-in through `[site].base_url`. Choose `rss_content = "summary"` (default)
or `"full"`, and mark collection pages with **`#rss(true)`**. Article `rss` defaults
to **false**. Only a marked collection's direct embeds become items, deduplicated
across collections; marked containers themselves are excluded. No container means
an empty enabled feed. The sitemap independently includes all compiled articles.

Preview uses `--port`, broadcasts the same revision to every client, avoids
no-op reloads, serves last-good pages during pre-publication failures, and waits
for in-flight builds on shutdown.

## Native PDF books and shared layout

`typsite pdf` builds one native document from the entry's embed forest and ordered
`--appendix` roots. Optional `--front-cover` / `--back-cover` add PDF-only covers;
`[layout].module` selects shared Typst HTML/PDF page furniture. `lib/pdf.typ`,
`layout.typ`, and the example cover files are optional; `links.typ` is not optional
when merging the updated helper set. See [PDF migration and limitations](https://github.com/Glomzzz/typsite/blob/main/docs/pdf.md#upgrading-helpers).

Template headers compose with the footnote-reset header. Sparse headings are
normalized before layout; headings produced inside opaque contexts fail with an
actionable diagnostic rather than publishing incorrect numbering. Arbitrary
native labels are still document-global. Keep duplicate-label, contextual
heading, and custom HTML compatibility limitations in mind when porting a site.

The release smoke gate now requires actual PDF compilation using each downloaded
native binary, with covers/layout, no-op checks, failed-build recovery, HTML
ownership isolation, and clean-build byte equivalence. Local success is not a
substitute for green exact-revision Windows/macOS/Linux/MSRV/Nix checks.
